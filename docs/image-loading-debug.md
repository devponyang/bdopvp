# 이미지/비디오 엑박(깨진 이미지) 문제 해결

## 🔍 문제 상황
업로드는 성공하지만 이미지/비디오가 엑박(X 표시)으로 표시됨

## 🛠️ 적용된 개선사항

### 1. 비디오 태그 개선
- `<source>` 태그 추가로 브라우저 호환성 향상
- MIME 타입 자동 설정 (MOV, MP4, WebM)
- 대체 텍스트 추가

### 2. 이미지 로딩 에러 처리
- `onerror` 핸들러 추가
- 로딩 실패 시 에러 메시지 표시
- 로딩 성공/실패 콘솔 로그 출력

## 🔧 디버깅 방법

### 1단계: 브라우저 개발자 도구 열기
```
F12 키 또는 우클릭 > 검사
```

### 2단계: 콘솔 탭 확인
다음과 같은 로그를 확인하세요:

**성공 시:**
```
이미지 로딩 성공: /api/images/tip-images/1759837434914_xxx.gif
```

**실패 시:**
```
이미지 로딩 실패: /api/images/tip-images/1759837434914_xxx.gif
```

### 3단계: 네트워크 탭 확인
1. **Network** 탭 클릭
2. 엑박이 뜬 이미지를 찾기
3. **Status** 컬럼 확인:
   - `200`: 성공 (파일 로딩됨)
   - `404`: 파일을 찾을 수 없음
   - `403`: 접근 권한 없음
   - `500`: 서버 내부 오류

### 4단계: 실제 URL 확인
1. 엑박이 뜬 이미지 우클릭 > **새 탭에서 이미지 열기**
2. URL이 다음 형식인지 확인:
   ```
   http://localhost:3000/api/images/tip-images/파일명
   ```

## 🎯 가능한 원인과 해결방법

### 원인 1: 서버가 재시작되지 않음
**증상:** 업로드는 되지만 이미지가 안 보임
**해결:** 
```bash
# Ctrl+C로 서버 중지
npm run dev  # 서버 재시작
```

### 원인 2: MOV 파일 브라우저 미지원
**증상:** MOV 파일만 엑박
**해결:** MOV는 일부 브라우저에서 지원하지 않음
- Chrome: 제한적 지원
- Firefox: 미지원
- Safari: 지원
**권장:** MP4나 WebM 형식 사용

### 원인 3: API 이미지 서빙 경로 문제
**증상:** 네트워크 탭에서 404 에러
**해결:** URL이 올바른지 확인
```
올바른 형식: /api/images/tip-images/파일명
잘못된 형식: /tip-images/파일명
```

### 원인 4: 파일이 실제로 저장되지 않음
**증상:** 업로드 성공 메시지는 뜨지만 파일이 없음
**해결:** 파일 존재 확인
```bash
# PowerShell에서 확인
Get-ChildItem public\tip-images | Sort-Object LastWriteTime -Descending | Select-Object -First 5
```

### 원인 5: CORS 문제
**증상:** 콘솔에 CORS 에러 표시
**해결:** 이미 `next.config.ts`에 헤더 설정되어 있음. 서버 재시작 필요

## 🎬 MOV 파일 특별 주의사항

### MOV 파일 브라우저 호환성
- **Safari (Mac)**: ✅ 잘 작동
- **Chrome (Windows)**: ⚠️ 제한적 작동 (코덱에 따라 다름)
- **Firefox**: ❌ 대부분 미지원

### 권장 사항
1. **MP4로 변환**: MOV 대신 MP4 사용 (가장 호환성 좋음)
2. **WebM 사용**: 크롬/파이어폭스에서 잘 작동
3. **여러 포맷 제공**: 서버에서 자동 변환 고려
